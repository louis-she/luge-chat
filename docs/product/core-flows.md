# 路鸽 · 真机核心流程

> **文档性质**：产品说明 + 必要技术细节。改功能时同步改本文。  
> **范围**：真机默认路径（火山 RTC「打电话」）。不含模拟器 / HTTP 旧语音回退。  
> **更新**：2026-07-28（含 §6 PostGIS / 高德澄清）

---

## 1. 产品在解决什么

路鸽是自驾场景的语音导游：用户开车时点开 App，像打电话一样和 AI 对话；系统也能在合适时机**主动开口**讲路边风景名胜。

真机上，语音的听/说/打断由**火山引擎 RTC + 智能体**完成；「车在哪、周边有什么、扣不扣次、记不记足迹」由路鸽自建后端（`api.luge.chat`）负责。

---

## 2. 总架构（真机）

```
┌─────────────────┐     RTC 音视频房间      ┌──────────────────────────┐
│  iOS / Android  │ ←──────────────────→ │ 火山：ASR + LLM + TTS    │
│  Expo App       │                      │ （可打断、全双工）         │
└────────┬────────┘                      └────────────┬─────────────┘
         │ 进房 Token / StartVoiceChat                │ 服务端回调
         │ 上报 GPS / 主动讲解 External TTS           │ Function Calling
         ▼                                            ▼
              ┌─────────────────────────────────────────┐
              │  api.luge.chat（Supabase Edge Functions） │
              │  · volc-voice-chat（进房、启停智能体）      │
              │  · volc-voice-callback（扣次、FC、足迹）    │
              │  · luge-chat（主动讲解判定）               │
              │  · 地理缓存 + 高德 Web 服务               │
              └─────────────────────────────────────────┘
```

| 层级 | 职责 |
|------|------|
| App | 进房/挂断、麦克风、GPS 上报、主动讲解触发与播报、配额展示 |
| 火山 | 实时语音识别、对话、TTS、用户打断 |
| 路鸽后端 | 配额、地理检索、足迹、主动讲解选点与文案 |

**密钥**：高德 `AMAP_WEB_KEY`、火山 RTC/OpenAPI 等只在服务器；客户端不直连高德。

## 3. 会话生命周期

用户在雷达页点「路鸽」≈ 拨通电话；再点 ≈ 挂断。

| 步骤 | 谁做 | 说明 |
|------|------|------|
| 1. 校验额度 | App → `volc-voice-chat` | 用尽则不开通；提示购买 |
| 2. 发 RTC Token + 进房 | App + `volc-voice-chat` | 音频房间 |
| 3. `StartVoiceChat` | `volc-voice-chat` → 火山 | 挂上路鸽人设、欢迎语、FC 工具 |
| 4. 循环上报位置 | App | 供 FC「查周边」与足迹用当前坐标 |
| 5. 通话中问答 / 主动讲解 | 见下文两章 | |
| 6. 挂断 | App → 停智能体 + 退房 | 刷新剩余次数 |

通话过程中，火山通过 **RTS 回调** 打到 `volc-voice-callback`（如 `answerFinish`、字幕、Function Call）。

## 4. 问路（用户主动说话）

### 4.1 用户感知

用户问例如：「左边那条河叫什么？」「前面那座山是啥？」  
AI 口语回答，可随时打断。有登录时，一轮完整问答可能写入**足迹**。

### 4.2 流程

```
用户说话
  → 火山 ASR
  → 火山大模型组织回答
      │
      ├─ 需要地理信息时
      │     Function Call：get_nearby_landmarks
      │       → volc-voice-callback
      │       → 先查本地地理缓存
      │       → 未命中再高德「周边搜索」
      │       → 结果回传给火山模型
      │
      └─ TTS 播给用户
  → 回调 answerFinish
      → 按 RoundID 去重，扣 1 次问路额度
  → 字幕/问答落库齐后
      → 尝试写入或匹配足迹（登录用户）
```

### 4.3 扣次规则（问路）

| 时机 | 行为 |
|------|------|
| 进房前 | 额度已用尽 → 不允许开始通话 |
| AI **说完一句**（`answerFinish`） | 扣 **1 次**；同一 `RoundID` 只扣一次 |
| 通话中途用尽 | 当前不自动挂断；下次进房会被拦 |

扣次身份：登录用户用账号额度；游客用设备维度额度（会话上绑定 `luge_user_id` / `device_key`）。

**为什么要 `RoundID` 去重：**  
扣次完全依赖火山服务端回调，不信 App 自报。同一轮 `answerFinish` 可能因网络重试、对方重复投递而被打多次；若不去重，一次问答会扣多次费。  
实现上表 `voice_chat_round_charges` 对 `(task_id, round_id)` 做唯一约束：同一通话任务里，每个 Round 只成功扣一次，重复回调直接忽略。  
产品约定仍是「AI 成功答完一轮再扣」；RoundID 去重是这条规则的防重复保险，不是给用户看的「问了几轮」计数。

### 4.4 地理怎么查（问路）

工具：`get_nearby_landmarks`（实现：`volc-voice-chat/nearbyLandmarks.ts`）。

1. 用客户端上报的最新经纬度（可带朝向）  
2. **优先** `geo_landmarks_cache`（PostGIS 半径检索）  
3. 缓存空 → 高德 `/v3/place/around`  
4. 结果整理成简短列表回给模型（含相对方向、距离）

模型回答内容由火山侧生成；路鸽保证「周边事实」来自缓存/高德，而不是模型瞎编坐标。

> PostGIS / 高德各自干什么，见 **§6**。不要把「撞缓存」理解成「逆地理」。

### 4.5 足迹（问路相关）

- **不**在用户只听主动讲解时写足迹。  
- 用户**主动问完一轮**（问句 + 答句能对齐）后，后端尝试：匹配已有足迹或新建。  
- 若上一句刚播过主动讲解，且用户在追问同一 POI，可视为「延续深聊」，有利于归到同一足迹。

实现落在 `volc-voice-callback`（字幕 / `voice_chat_round_dialog` + 足迹逻辑）。路测验收仍以真机为准。

## 5. 主动讲解（系统主动开口）

### 5.1 用户感知

「我的」里打开**主动讲解**后，开车满足条件时，路鸽会自己讲附近**一处风景名胜**（短口播）。  
同一景点**当天不重复讲**（按上海日历日）。

主动讲解**每次发起检查都会扣 1 次**问路额度（即使最终决定不播，例如附近没有候选）。

### 5.2 何时启用

同时满足：

- 用户打开了主动讲解开关  
- 真机雷达上**路鸽通话已接通**（`inCall`）  
- 非「忙」状态（避免和进房握手等冲突）

### 5.3 触发门槛（客户端）

启动通话后先记一个**查询锚点**。之后 GPS 更新时检查：

| 条件 | 默认 | 含义 |
|------|------|------|
| 位移 | ≥ **20 km**（可在「我的 → 高级设置」改） | 相对上次查询锚点 |
| 查询间隔 | ≥ **10 min**（可配） | 距上次查询 |
| 开口间隔 | ≥ **15 min**（可配） | 距上次真正播报 |

位移与查询间隔必须**同时**满足才请求后端。路测可用高级设置里的「路测宽松 / 极松调试」预设，无需改环境变量或重编译。

实现：`lib/useProactiveGuide.ts` + `lib/proactiveSettings.ts` + `app/advanced-settings.tsx`。

### 5.4 后端选点与文案（`luge-chat` · `mode=proactive`）

```
门槛满足 → App 调 luge-chat（带当天已讲 POI 键）
  1. 扣 1 次额度
  2. 高德逆地理（地址上下文，1 次）
  3. 高德周边搜索：types 仅「风景名胜」，约 8km（1 次）
  4. 代码去重（近距离、名称包含关系，如「芙蓉岛公园」vs「…一号馆」）
  5. 过滤「今天已讲过」
  6. 无候选 → skip（不播，但已扣次）
  7. 有候选 → DeepSeek 必须从列表里选恰好 1 个写口播（篇幅：短 80～160 / 中 150～280 / 长 280～450，高级设置可配）
     （名称对不上则回退最近候选；禁止编造列表外地名）
  8. 返回文案 + 选中 POI
→ App 用火山 ExternalTextToSpeech 在通话中播报
→ 记下当天已讲 + 「最近主动讲解 POI」上下文（供后续追问/足迹）
```

**候选类型约束**：主动讲解只用高德「风景名胜」，不把河流、乡镇、商铺等混进可选列表。  
主动讲解选点**不依赖** PostGIS 撞库；PostGIS 缓存主要服务问路 FC（见 §6）。

### 5.5 和问路的关系

| | 问路 | 主动讲解 |
|--|------|----------|
| 触发 | 用户说话 | 20km + 10min（再加开口冷却） |
| 语音通道 | 火山智能体主对话 | 通话中插入 External TTS |
| 地理 | FC 缓存→高德周边（类型更广） | 固定风景名胜周边 + 逆地理 |
| 扣次 | AI 说完扣 1 次 | 每次检查扣 1 次 |
| 足迹 | 问答后可写 | 本身不写；用户接着问才可能写 |

## 6. 位置、PostGIS 与高德（概念澄清）

### 6.1 App 上报什么

真机循环上报的是 **经纬度**（通常还有 **朝向 heading**），例如 `(30.65, 104.06)`。  
这只是地球上的一个点，**本身没有地名**。地名要么来自我们库里已存的记录，要么来自高德接口。

### 6.2 PostGIS 不是「逆地理」

容易混淆的两件事：

| | **高德逆地理** | **PostGIS（路鸽里）** |
|--|----------------|----------------------|
| 干什么 | 问地图服务：「这一点附近地址/路叫什么」 | 在**自家库**里：「半径 N 米内有哪些我们存过的地标」 |
| 数据从哪来 | 高德全国底图 | 表 `geo_landmarks_cache`（路鸽自己沉淀） |
| 类比 | 问高德地图 App | 在自家清单里按距离筛（带空间索引，很快） |
| 接口/能力 | `/v3/geocode/regeo` | PostgreSQL + PostGIS：`geometry` + GIST + `nearby_geo_landmarks` |

**逆地理** = 坐标 → 地址文字（区、路、附近描述等）。  
**PostGIS** = 空间数据库能力：存点/线/面，做距离、半径、包含等查询。  
路鸽当前主要用到：把地标存成 **Point + 属性**，用半径检索「附近有谁」。名字在入库时就已经有了，不是 PostGIS「算」出来的。

PostGIS **还能**做（能力储备，不限于当前已用）：线（河段）、面（景区边界）、点是否在多边形内、缓冲区、最近邻等。产品上若以后做「进了景区围栏再讲」，会用到面/包含，而不是逆地理。

### 6.3 `geo_landmarks_cache` 存什么

大致字段含义：

- **位置** `geom`：PostGIS 几何（当前多为点）  
- **名称 / 类型**：如「都江堰」、风景/河/桥/山…  
- **讲解文案** `ai_formatted_story`：以往问答沉淀，撞库命中时可复用  
- **高德 `amap_poi_id`**（有则存）：去重与更新  
- **有效期、命中次数** 等元数据  

它存的是：**我们认过、讲过、值得以后再撞的地理知识点**，不是全国路网底图。

常见写入路径：问路时高德命中了某 POI、回答完成后，把该点 + 故事写入/更新缓存。下次开到附近，FC 可能直接命中，少打高德。

### 6.4 和两条业务线的关系

**问路 FC `get_nearby_landmarks`：**

```
上报 (lat, lng [, heading])
  → ① PostGIS：半径搜 geo_landmarks_cache
  → ② 若空：高德「周边搜索」place/around（附近 POI，不单是「当前路段名」）
  → 列表（名、距离、左前方/右前方…）回给火山模型
```

**主动讲解：**

```
上报坐标
  → 高德逆地理（地址上下文）
  → 高德周边：仅「风景名胜」
  →（当前）不靠 PostGIS 选讲哪一个
```

**易错理解（对照）：**

1. App 上报经纬度 —— **对**  
2. 先 PostGIS，PostGIS 主要做逆向（坐标→名称）—— **不对**；PostGIS 是在已有地标库里找「附近有谁」  
3. 撞库失败就调高德拿当前路段名 —— **不完全对**；失败后主要是高德**周边 POI 搜索**；路段/地址更偏**逆地理**，用在主动讲解等上下文，不是 FC 查周边的唯一目标  

### 6.5 外部地图提供方抽象（换厂商用）

业务代码**不直接**写死 `restapi.amap.com`。统一走：

- 模块：`supabase/functions/_shared/mapPoi/`
- 接口：`around`（周边 POI）+ `regeo`（逆地理）
- 当前实现：仅 **高德**（`createAmapProvider`）
- 切换开关：环境变量 `GEO_MAP_PROVIDER`（默认 `amap`；`tianditu` 占位，尚未实现）

问路 FC、主动讲解、开发预览都经此抽象。以后接天地图时：新增 `tianditu.ts` adapter + 在 `getMapPoiProvider` 分支即可，业务阈值尽量不动。

## 7. 高德调用一览（真机相关）

全部在 Edge Function，计费常见为「周边搜索」「逆地理编码」。

| 场景 | 接口 | 大致次数/次请求 |
|------|------|----------------|
| 问路 FC `get_nearby_landmarks` | 周边搜索（缓存未中时） | 0～1 |
| 主动讲解 | 逆地理 + 风景名胜周边 | **2** |
| 开发：主动讲解地图预览 | 仅风景名胜周边 | **1**（不扣次、不调大模型） |

开发预览入口：「我的 → 主动讲解地图」。可拖动查询位置；预览接口勿做成跟 GPS 心跳狂刷（成本敏感）。

## 8. 配额与账号（摘要）

- 计费单位：**问路次数**（主动讲解的「检查」也消耗同一种次数）。  
- 登录用户 / 游客（设备）两套身份；App「我的」展示剩余次数。  
- RTC：进房前拦截用尽；扣次以服务端 `answerFinish` / `proactive` 为准，不以客户端自报为准。

### TODO（暂不做）· 计费演进

当前按「次数」扣费偏粗：短问短答与长聊同价，也和火山实际成本（token / TTS 时长等）不对齐。

**更合理的方向（待调研与产品定案）：**

1. 以**对话 token（及必要时的语音相关用量）**为计费/限额依据，而不是单纯 `answerFinish` 次数。  
2. **优先**：火山侧能否按路鸽体系内的**每个用户（或每个 RTC userId / 业务 user）**独立统计用量，路鸽后端再**拉取用量**做套餐、告警、对账。  
3. 若火山暂不支持按我方用户维度出账：再评估自建估算（回调里的 token 字段、自建计量）等次优方案。  

在未落地前，仍维持本文 §4.3 / §5 的「按次」规则与 RoundID 去重；改计费模型时需同步改后端、App 展示与本节。

## 10. 已知产品约定 / 后续改动时注意

1. **主动讲解检查即扣次**：即使用户听不到播报（无候选、开口冷却），检查请求已计费。若产品要改成「只有播报才扣」，需同时改后端与本文 §5。  
2. **风景名胜 only**：主动讲解候选不要再塞回河流/地名等，除非产品明确放开并改本文 §5.4。  
3. **当天去重**：键为规范化名称 + 可选高德 POI id；换设备不会共享，除非以后改为服务端去重。  
4. **改门槛 / 口播长短 / 搜索半径**：用 App「我的 → 高级设置」，不要再靠环境变量路测。  
5. **改扣次时机**：RTC 问路以 `answerFinish` 为准；不要改回客户端随意上报。  
6. **PostGIS vs 高德**：改地理策略时同步更新 §6，避免再把撞缓存写成「逆地理」。
7. **高级设置面向路测**：正式上架前可再收口哪些项对普通用户可见。
